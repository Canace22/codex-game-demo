# 实例：浏览器武侠竖切

本文件展示如何把通用流程实例化。它是示例，不是母版；复制到新项目时不得继承名称、数值、路径、运行时或发布方式。

## 1. 项目画像摘要

| 字段 | 实例值 |
| --- | --- |
| `project_id` | `GUIYUN` |
| 产品目标 | 10–15 分钟内完成一条原创 3D 武侠任务线 |
| 黄金路径 | 山门接援 → 山路 → 断桥轻功 → 村落 → 寺院防守 → 五人首领战 → 返回交付 |
| 启动方式 | 根目录静态入口、本地协议、静态 HTTP、静态托管 |
| 平台 | 桌面键鼠、手机横屏触控、手机竖屏旋转提示 |
| 非目标 | 账号、服务端、真实网络多人、运行时 AI API |
| 状态观测 | 文本状态函数、确定性时间步进、调试桥 |
| 发布 | 默认分支根目录静态部署 |

## 3. 实际 P0–P7 轨迹

| 阶段 | 实际产出 | 关键发现 |
| --- | --- | --- |
| P0 | 原创边界、完整任务、桌面/手机、静态启动要求 | 必须把概念图当设计语言，不当复制目标 |
| P1 | 空仓库、内置依赖方案、真实浏览器工具与协议风险 | 本地图片上传 GPU 存在安全差异 |
| P2 | 状态、角色职责、战斗数值、输入、世界区域和测试状态合同 | 自动化需要文本状态和确定性时间步进 |
| P3 | 可打开入口、山门、角色、移动、镜头、跳跃 | 方向键布尔值未归一会传播成 `NaN` |
| P4 | 山门至交付完整任务、轻功、三波防守、首领和队友 | 黄金路径先闭环，再优化美术 |
| P5 | 落水/倒地恢复、AI 贴地、实体分离、墙体碰撞、鼠标拖动、移动布局 | 位移、闪避、突袭和重置必须共享碰撞/贴地合同 |
| P6 | 标题图、远景、三张主题纹理、雨夜寺院和角色武器挂点 | 本地与 HTTP 纹理需两条明确消费路径 |
| P7 | 完整回归、自然战斗、移动端、静态部署和验收记录 | 线上提交、资源响应和浏览器状态必须一致 |

## 4. 实际验收证据摘要

| 场景 | 实际结果 |
| --- | --- |
| 最小启动 | 本地直接打开进入 3D 场景，方向键移动和跳跃可用，页面错误为 0 |
| 黄金路径 | 从接任务到 `COMPLETE`，六个落脚点、三种首领招式、玩家与四队友输出均被记录 |
| 失败恢复 | 落水回最近检查点；战斗失败不使任务倒退；碰撞阻止穿墙 |
| 关键机制 | 自然首领战 120.5 秒完成，治疗量 4387；防守 80.75 秒完成并保住 1 名村民 |
| 跨端 | 844×390 横屏摇杆、镜头和八按钮通过；390×844 显示旋转提示 |
| 视觉媒体 | 本地安全纹理和 HTTP 图像纹理两条路径通过，控制台错误为 0 |
| 发布 | 静态站点构建成功，入口和三张纹理在线响应成功 |

## 5. 偏差如何登记

| ID | 实际偏差 | 处理方式 |
| --- | --- | --- |
| `DEV-GUIYUN-001` | UI 键帽与运行时部分键位漂移 | 保持 open，相关输入提示不能标记完全 verified |
| `DEV-GUIYUN-002` | 深入 E2E 脚本位于忽略目录 | 后续迁入版本化证据工具 |
| `DEV-GUIYUN-003` | 缺多名新玩家的正式 10–15 分钟计时 | 自动化通关不替代人工节奏样本 |
| `DEV-GUIYUN-004` | 本地和 HTTP 使用不同纹理来源 | 作为协议限制接受，两条路径分别验收 |
| `DEV-GUIYUN-005` | 缺 warning、低端设备和性能证据 | 进入下一发布批次的扩展门禁 |

## 6. 可复用结论

- 第一个提交必须证明真实启动，不要等待完整系统。
- 黄金路径、失败恢复、跨端和视觉接入是不同批次，证据不能混写。
- 状态观测接口应在 P3 建立，而不是测试末期补做。
- 视觉资源必须进入真实镜头与 HUD 验收。
- 具体项目的协议差异、角色命名和数值应留在实例，不进入母版。

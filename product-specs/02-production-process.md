# 八阶段生产流程

## 1. 总览

```text
P0 需求与边界
  → P1 现状盘点
    → P2 规格与工作单
      → P3 最小可启动版本
        → P4 黄金路径闭环
          → P5 失败恢复与跨端
            → P6 视觉媒体与体验收口
              → P7 独立验收、发布与归档
```

每个阶段都遵循同一小循环：

```text
实现小改动 → 真实操作 → 短暂停顿 → 读取状态/截图/错误 → 修复 → 回归
```

任何阶段出现 L0 或 L1 失败时，不进入正式体验截图。

## 2. P0 需求与边界

目标：把需求变成可判断完成与否的项目画像。

必须冻结：

- 核心体验和黄金路径。
- 目标时长、平台、方向和输入方式。
- 启动与发布方式。
- 必须存在的正向、失败和恢复行为。
- 技术、版权、安全和网络边界。
- 明确不做的内容。

输出：项目画像、初始风险、成功定义。

退出条件：没有会改变产品形态的未决项；否则标记 `BLOCKED`。

## 3. P1 现状盘点

新项目确认可用依赖和最小入口；已有项目先读取真实代码、资源、测试和发布状态。

检查：

- 当前分支、提交、脏工作区和外部修改。
- 入口、模块、数据真源、资源路径和消费方。
- 已有测试、可观测接口、构建或静态启动方式。
- 桌面、手机、协议、浏览器或引擎差异。
- 已知缺陷和缺失证据。

输出：基线清单、依赖图、偏差初表。

退出条件：可以说明“现状是什么”“需求差什么”“哪些文件不能同时由多人修改”。

## 4. P2 规格与工作单

从基础目录选择最少产物，并实例化精确合同。

顺序：

1. 冻结项目 ID、状态 ID、角色/对象 ID、资源键和公共字段。
2. 写具体规格的输入、输出、消费方、不变量和验收。
3. 建立依赖与影响范围。
4. 将工作拆成单目标批次。
5. 为共享文件指定唯一写入者。
6. 定义证据路径和回滚点。

输出：批准的具体规格、工作单、验收矩阵。

退出条件：生产 Agent 不需要猜测路径、数量、条件或完成标准。

## 5. P3 最小可启动版本

目标：尽快得到真实运行环境中的最小可预览版本。

最低内容：

- 唯一入口和最小场景或页面。
- 主体可见，至少一个核心输入可用。
- 状态可观察，错误可收集。
- 目标启动方式真实可用。
- 建立开发记录并形成首个可预览提交。

此阶段不追求完整玩法和精美画面。先验证技术路径，再增加复杂度。

退出条件：目标环境可以启动、操作、截图并读取状态，阻断错误为零。

## 6. P4 黄金路径闭环

目标：完成从开始到成功结算的一条连续主流程。

要求：

- 每阶段有明确进入、目标、反馈和退出条件。
- 状态迁移单向可达，不依赖显示文案判断逻辑。
- 所有核心系统至少在黄金路径中真实消费一次。
- 关键角色、AI、资源和 UI 不是装饰占位。
- 完成态可以由结构化状态和画面同时确认。

先保证可通关，再补分支、美术和声音。

退出条件：自动化状态路径通过，并至少用一组真实输入完成关键交互。

## 7. P5 失败恢复与跨端

目标：把“能跑”变成“不容易软锁”。

必须覆盖：

- 失败、倒地、掉落、断线或非法输入后的恢复。
- 检查点、重试、重置和重复交互。
- AI、碰撞、地面、相机、武器或 UI 的空间冲突。
- 桌面键鼠与目标移动布局。
- 横屏、竖屏、窗口缩放和失焦输入清理。
- 自动步进与正常运行循环不会重复推进。

退出条件：失败不吞进度、不留下残留状态，目标设备主要输入可达。

## 8. P6 视觉媒体与体验收口

目标：在可玩主流程稳定后补主题一致性和可读性。

生产顺序：

1. 冻结风格锚点、颜色语义和消费尺寸。
2. 单资源生成或制作，保存来源和提示词。
3. 检查格式、尺寸、体积、版权和禁止项。
4. 接入真实消费材质、场景、角色或 UI。
5. 检查协议差异、加载失败回退和移动预算。
6. 在最终镜头、光照、天气、HUD 和目标视口中验收。

生成完成只算 L0；进入游戏并保持玩法可读才算 L3。

退出条件：主题统一、角色和危险可辨、资源失败不导致软锁，性能风险已记录。

## 9. P7 独立验收、发布与归档

顺序：

1. QA 重新读取批准规格和工作单。
2. 执行 L0、L1、L2、L3。
3. 修复后重验缺陷点、直接消费方和至少一条黄金路径。
4. 检查变更范围、提交内容和回滚点。
5. 获得外部发布授权后提交、推送和部署。
6. 确认线上提交、资源和浏览器状态一致。
7. 归档验收报告、偏差和下一批建议。

退出条件：版本可追溯，发布消费方通过，未关闭风险已经明确批准。

## 10. 提交点

以下情况形成独立提交：

- P3 最小入口首次可预览。
- P4 黄金路径首次闭环。
- P5 关键失败恢复或跨端首次通过。
- P6 视觉媒体批次完成接入。
- P7 发布规格和证据归档。

提交只包含当前批次文件，不混入其他所有者的修改。

## 11. 并行与串行

可并行：

- ID 和消费合同冻结后，不同文件的内容、视觉和测试计划。
- 稳定 API 下的资源生产与接入方案。
- 不共享写入文件的专项验证。

必须串行：

- 项目画像完成后再实例化具体规格。
- 具体规格批准后再修改产品代码。
- 共享入口、公共状态和资源注册表由唯一所有者修改。
- L0/L1 通过后再开始正式 L3。
- 发布提交完成后再登记线上证据。

## 12. 返工规则

- 规格冲突：退回 P2，不由实现 Agent 自行降低目标。
- 启动失败：停在 P3，先修第一个阻断错误。
- 黄金路径软锁：停在 P4/P5，保存最短复现和前后状态。
- 视觉遮挡玩法：退回 P6 调整表现，不改判定迁就画面。
- 线上与本地不一致：分别记录协议、缓存、资源和提交，不用 HTTP 200 代替体验验收。

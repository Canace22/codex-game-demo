# 《归云录：江岸危局》策划与内容产物规格

> 项目实例：`codex-game-demo` 原创浏览器 3D 武侠 MMORPG 竖切原型
>
> 覆盖范围：设计总纲、世界与角色、任务状态机、关卡、轻功、战斗、首领、UI 文案和跨端输入
>
> 事实口径：只登记当前仓库已实现或已明确约束的内容，不把未来设想写成现有能力。

## 1. 四级分类与通用生产契约

每项内容产物同时声明产物类型、产物子类型、产物基础规格和本项目具体规格。

| 层级 | 定义 | 本库要求 |
| --- | --- | --- |
| 产物类型 | 同一生产阶段和业务目标的一组产物 | 设计总纲、叙事、任务、关卡、移动、战斗、UI/输入 |
| 产物子类型 | 可独立生成、评审、返工的最小单元 | 例如任务状态机、轻功规则、首领招式、HUD 文案 |
| 产物基础规格 | 可复用字段、约束、引用和验收方式 | 每张生产卡的“产物基础规格” |
| 本项目具体规格 | 《归云录：江岸危局》的确定内容 | 精确状态、ID、数值、路径、消费方和断言 |

后续拆出的单项规格必须使用以下元数据：

```yaml
catalogId: GY-XX-XX
specId: DSN.SUBTYPE.GUIYUN
productType: 产物类型
productSubtype: 产物子类型
version: 1.0.0
status: draft | approved | in_production | blocked | verified | deprecated
sourceBrief: 上游需求或产物 ID
dependencies: [DSN.UPSTREAM.GUIYUN]
outputTargets: [仓库内目标路径]
consumers: [消费模块或 Agent]
owner: agent-or-role
```

通用规则：

1. 规格 ID 使用 `DSN.*.GUIYUN`；运行时 ID 必须逐字匹配当前代码，不以显示名建立隐式关联。
2. 状态、数值、触发条件和冷却进入配置或结构化规格；显示文案与逻辑条件分离。
3. 每个任务阶段都要给出进入条件、退出条件、可见反馈、失败恢复和验收断言。
4. 每个角色、区域、技能、敌人和交互点都要有生产者、消费方与实现路径。
5. 修改 Stage、Spawn、Zone、角色 role 或动作 action ID 时，必须全局扫描引用并回归完整流程。
6. 规格不得引入现有商业武侠作品的角色、门派、地图、图标、招式或标志性视觉设计。
7. 当前实现仍含大写枚举、连字符实体 ID 等历史形式；迁移为统一 `snake_case` 前不得静默改名。

## 2. 设计总纲类产物

### GY-DC-01 游戏切片设计总纲

- **基础规格 ID / 具体规格 ID**：`DSN.SLICE` / `DSN.SLICE.GUIYUN`
- **版本 / 状态 / 责任 Agent**：`1.0.0` / `draft` / `design_content_agent`
- **产物类型 / 子类型**：设计总纲 / 端到端可玩切片
- **产物基础规格**：必须冻结平台、游玩时长、核心循环、场景流、会话策略、技术边界、视觉锚点和质量门禁。
- **本项目具体规格**：10 至 15 分钟的第三人称 3D 武侠任务；玩家带四名 AI 队友从山门出发，经山路与断桥抵达江村和寺院，完成保护战、首领战并回山交付。
- **平台**：桌面浏览器与手机；移动端以横屏为主要布局，竖屏只保留可读提示和旋转引导。
- **技术边界**：静态 `index.html` + 内置 Three.js r149 + 原生 JavaScript/CSS；无构建前置、无服务端、无运行时 AI API。
- **会话策略**：仅内存态；刷新重新开始；完成界面的“再历此程”通过 `location.reload()` 重置。
- **核心体验**：连续探索、第三人称移动、必须参与路线的轻功、五人协作战斗、可辨认的首领机制。
- **视觉锚点**：晴岚山谷与墨蓝雨夜古寺；友方青绿、治疗象牙金、危险暗绯红；只提取概念图设计语言。
- **来源证据路径**：`README.md`、`index.html`、`src/core.js`、`src/world.js`、`src/combat.js`、`src/materials.js`。
- **输出目标**：设计总纲 Markdown、状态/数值配置、浏览器验收记录。
- **消费方**：任务、关卡、战斗、UI、资源、测试 Agent；游戏实现模块。
- **验收标准**：从 `index.html` 启动；由接任务走到 `COMPLETE`；桌面和手机横屏可操作；控制台错误为 0。
- **AI Agent 生产指令**：先登记真实 Stage 与数值，再写体验描述；任何超出现有闭环的内容标为非目标或独立增量。

### GY-DC-02 范围与完整闭环声明

- **基础规格 ID / 具体规格 ID**：`DSN.SCOPE` / `DSN.SCOPE.GUIYUN`
- **版本 / 状态 / 责任 Agent**：`1.0.0` / `draft` / `design_content_agent`
- **产物类型 / 子类型**：设计总纲 / 垂直切片范围基线
- **产物基础规格**：流程节点必须包含玩家目标、进入条件、交互、状态效果、下一节点、失败恢复和可见证据。
- **本项目具体规格**：开始界面 → 山门听取求援 → 山路击败 2 名影徒 → 轻功过断桥 → 询问江村里正 → 寺院三波守卫 → 首领登场 → 五人击败沈烬尘 → 流光桥返山 → 交付完成。
- **主线形态**：单线、无分支、无可选支线；每一节点只有一个确定后继状态。
- **完成条件**：首领死亡进入返程，玩家在山门执事 4.8 米内交互进入 `COMPLETE`。
- **失败条件**：玩家倒地或三名保护村民全部倒下；当前遭遇延时 2 秒后重置，任务 Stage 不倒退。
- **正反馈**：任务卡、阶段进度、世界标记、Toast、音效、首领条、结算用时和倒地次数。
- **来源证据路径**：`src/config.js:6-55`、`src/core.js:236-341,541-544,683-710`、`src/combat.js:647-741`。
- **输出目标**：闭环流程表、状态轨迹、失败恢复轨迹、完成截图。
- **消费方**：任务编排 Agent、关卡 Agent、自动化测试。
- **验收标准**：十个 Stage 均可达；无跳过山门、村民简报或首领的正常路径；失败后仍能继续完成。
- **AI Agent 生产指令**：正向模拟一次完整路线，再分别注入落水、玩家倒地、村民全灭三类失败，确认回到可操作状态。

## 3. 世界与叙事内容类产物

### GY-NR-01 世界前提、地域与语调

- **基础规格 ID / 具体规格 ID**：`DSN.WORLD` / `DSN.WORLD.GUIYUN`
- **版本 / 状态 / 责任 Agent**：`1.0.0` / `draft` / `design_content_agent`
- **产物类型 / 子类型**：叙事内容 / 世界前提与地域锚点
- **产物基础规格**：包含标题、冲突钩子、玩家身份、势力/地点、威胁、语调、反复意象、原创性禁区。
- **本项目具体规格**：标题《归云录》，章节“江岸危局”；栖岚山门收到澄江村求援，蚀心影徒围攻江岸，走火入魔的武林高手沈烬尘试图在古寺强行破境。
- **玩家身份**：未命名持剑“少侠”，作为五人小队的直接操作者与队令发起者。
- **地域顺序**：`栖岚山门 → 山路 → 照影河断桥 → 澄江村 → 照水寺战场 → 归云石径 → 栖岚山门`。
- **主题问题**：个人武力必须与同伴分工、保护弱者和克制失控力量结合，才能平息危局。
- **语言风格**：短句、命令式目标、克制武侠白描；反复使用山岚、江水、古寺、真气与归途意象。
- **命名约束**：玩家可见地点统一称“照水寺”；`src/world.js` 中 3D 组名“残月古寺”属于现有内部别名，后续应统一但本轮不得假称已完成。
- **原创性禁区**：不使用任何现有游戏门派、人物、技能图标、地图名、服饰纹样或标志性台词。
- **来源证据路径**：`index.html:15-37`、`src/config.js:44-61`、`src/world.js:390-391,328-334,505-577`、`src/core.js:244-277`。
- **输出目标**：世界锚点表、术语表、地点注册表、禁用清单。
- **消费方**：任务文案、关卡、角色、环境资源与音频 Agent。
- **验收标准**：所有玩家可见地点名与任务目标一致；不存在未登记专名；概念图只作为色彩和构图参考。

## 4. 任务与关卡内容类产物

### GY-QS-01 主线任务状态机

- **基础规格 ID / 具体规格 ID**：`DSN.QUEST` / `DSN.QUEST.GUIYUN`
- **版本 / 状态 / 责任 Agent**：`1.0.0` / `draft` / `design_content_agent`
- **产物类型 / 子类型**：任务内容 / 单线状态机
- **产物基础规格**：每个状态包含 `stageId/entry/exit/objective/progress/sideEffects/failureRecovery/evidence`；状态 ID 不得由文案推断。

| Stage | 进入条件 | 退出条件 | 主要可见进度 |
| --- | --- | --- | --- |
| `TITLE` | 页面加载 | 点击“踏入江湖” | 开始界面 |
| `GATE_OFFER` | 开始游戏 | 与山门执事交互 | “靠近后交互” |
| `ROAD_TO_BRIDGE` | 接受求援 | 两名山路影徒清除且玩家 `z<=12.5` | `影徒 n/2` |
| `BRIDGE_CROSSING` | 到达断桥北端 | 玩家 `z<-31.2` | 疾冲/二段跳使用标记；落脚石 `n/6` |
| `VILLAGE_ARRIVAL` | 抵达对岸 | 已询问里正且玩家 `z<-96` | 简报前交互，简报后“寺院方向” |

| `BOSS_FIGHT` | 演出结束 | 沈烬尘 HP 降至 0 | 首领伤害进度与当前招式 |

- **注意**：`BRIDGE_CROSSING` 的代码退出条件只检查位置；疾冲、二段跳和六个落脚石是关卡空间促成与统计指标，不是额外布尔门锁。
- **来源证据路径**：`src/config.js:6-55`、`src/core.js:236-315,541-544,683-710`、`src/combat.js:647-741`。
- **输出目标**：状态表、状态图、逐边测试夹具、文案映射。
- **消费方**：核心流程、世界显隐、战斗模式、HUD、E2E 测试。
- **验收标准**：正常输入只按表中方向迁移；进入状态时副作用只执行一次；`COMPLETE` 后游戏输入不再推进世界状态。

- **允许的原型抽象**：低多边形角色、程序化碰撞代理、内存会话、确定性伪随机 AI、`file://` 安全内存纹理回退。
- **来源证据路径**：`README.md:1-8,28-46`、`index.html:39-49`、`src/core.js:683-710`、`src/materials.js`。
- **输出目标**：范围清单、变更申请模板、版本影响评估。
- **消费方**：产品、所有生产 Agent、代码审查和发布门禁。
- **验收标准**：网络面板无业务 API；刷新不声称保留进度；页面可静态启动；所有新增需求先判断是否越界。

- 修改 Stage、任务触发或完成条件：回归 P1-P6，并重跑完整任务与三类失败轨迹。
- 修改 Spawn、Zone、Surface 或碰撞：回归 P2-P6，检查移动、AI 贴地、镜头与返程桥。
- 修改动作、队友或敌人数值：回归 P3-P6，重跑防守和自然首领战。
- 修改首领招式：回归 P4-P6，覆盖预警、命中、躲避、破招成功与失败。
- 仅修改文案：回归 P5-P6，扫描旧术语并检查桌面与手机最长文本。

## 9. 当前实现向内容工业化迁移的提示

当前设计真源仍分散在代码中：

1. Stage、数值、任务标题和角色显示信息位于 `src/config.js`。
2. 状态转换、动态目标、交互、轻功与恢复位于 `src/core.js`。
3. 队友、敌人、波次、治疗和首领招式位于 `src/combat.js`。
4. Zone、Spawn、Surface、断桥平台和地点内部名位于 `src/world.js`。
5. 动作 fallback、队伍 fallback 与移动端控件位于 `src/ui.js`，其中存在少量旧命名漂移。

工业化后应以本规格库登记的稳定规格 ID 为审查入口，再生成配置、内容数据和实现代码。首次外置应优先处理 Stage/任务文案、角色注册表、战斗数值和 UI 文案；外置过程中必须保持现有 `GY.Stage`、action、role、Spawn 和 Zone 接口，除非另有带迁移表的版本升级产物。

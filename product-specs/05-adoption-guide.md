# 新项目接入指南

## 1. 首次接入

在新仓库中复制整个 `product-specs/`，然后按以下顺序执行：

1. 复制项目画像模板到 `product-specs/instances/<project-id>/project-profile.md`。
2. 填写项目 ID、核心闭环、启动方式、目标平台、非目标和真实消费方。
3. 从基础产物目录选择本批需要的条目。
4. 为每项输出复制产物规格模板，生成项目具体 ID。
5. 使用工作单模板创建一个单目标批次。
6. 指定主责 Agent、允许路径、冻结合同和证据目录。
7. 按 P0–P7 推进并持续记录问题与修复。
8. 使用验收报告和偏差表关闭批次。

不要复制示例项目的角色、状态、路径、数值、框架或发布方式。

## 2. 三十分钟启动检查

完成以下问题即可开始 P2：

- 玩家或用户最终要完成什么？
- 最短黄金路径是什么？
- 哪些失败必须可恢复？
- 谁真实消费每项输出？
- 项目如何启动、观察状态、收集错误？
- 哪些平台和视口必须通过？
- 哪些内容明确不做？
- 谁可以决定规格，谁可以发布？

任何答案缺失都写入项目画像的阻塞项。

## 3. 选择产物，不要全量复制

常见最小竖切批次：

| 目的 | 建议产物 |
| --- | --- |
| 新建可玩竖切 | `PRJ.PROFILE`、`DSN.SLICE`、`DSN.FLOW`、`ENG.RUNTIME`、`QA.PLAN` |
| 新增玩法系统 | `DSN.SYSTEM`、`ENG.RUNTIME`、`QA.PLAN`、`QA.EVIDENCE` |
| 新增视觉资源 | `VIS.PACK`、消费侧 `ENG.RUNTIME`、`QA.EVIDENCE` |
| 修复跨端缺陷 | 受影响 DSN/ENG、`QA.PLAN`、`OPS.DECISION` |
| 发布 | `QA.EVIDENCE`、`OPS.RELEASE`、必要的 `OPS.DECISION` |

如果一项规格没有真实消费方，不要生产它。

## 4. 项目适配边界

本库提供公开产物合同、工作单和验收方法，不假设能直接理解所有游戏编辑器或工程格式。

游戏项目负责：

- 导出能力、目录、稳定 ID、字段限制和项目版本。
- 将标准产物转换到自己的数据、编辑器和运行时。
- 返回导入结果、对象 ID、警告和错误。
- 提供项目专属检查和真实运行证据。

外部生产平台负责：

- 按批准规格生成内容、资源或变更包。
- 保持 ID、引用、依赖和版本。
- 执行通用检查并交付可追溯证据。

## 5. 何时扩展流程

只有出现以下情况才新增模板或门禁：

- 新产物具有不同消费方和生命周期。
- 现有字段无法表达关键安全或版本约束。
- 同类缺陷在至少两个批次重复出现。
- 项目需要正式 Schema、CLI、SDK 或编辑器导入协议。

一次性字段优先写入项目具体规格，不污染通用母版。

## 6. 完成一次首次实例化

首次接入完成应具备：

- 一个已批准项目画像。
- 一份最小产物目录和依赖关系。
- 一张单目标工作单。
- 一个可启动或可消费的最小输出。
- 一份 L0–L3 验收报告。
- 一份偏差表，即使内容为“无”。
- 一个绑定提交的证据目录。

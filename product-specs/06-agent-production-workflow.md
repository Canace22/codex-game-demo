# AI Agent 标准化生产工作流

版本：`1.0.0`

## 1. 适用范围

本工作流用于持续迭代《归云录：江岸危局》的设计内容、Three.js 静态运行时、原创视觉资源和跨端质量证据。它以已批准规格为生产合同，不允许 Agent 通过阅读自然语言需求后直接改动共享接口。

当前能力边界：

| 能力 | 当前合同 |
| --- | --- |
| 运行形态 | 无构建步骤的 classic script 静态站点 |
| 启动协议 | `file://`、静态 HTTP、GitHub Pages |
| 平台 | 桌面与手机横屏；手机竖屏显示旋转提示 |
| 运行时 | 内置 Three.js r149，全局 `window.GY` 模块 |
| 网络 | 无账号、无服务端、无真实多人、无运行时 AI API |
| 内容 | 单条 10–15 分钟目标任务线与五人 AI 小队 |
| 资源 | 项目内原创 PNG/JPEG、程序化几何、合成音效 |
| 自动化接口 | `window.render_game_to_text()`、`window.advanceTime(ms)` |

## 2. 合同边界

```text
需求 / GCP 工作台
  → 已批准具体规格与工作单
    → Agent 生产文件、资源或代码
      → 项目本地检查
        → 游戏运行时真实消费
          → 浏览器验收与报告
```

- 规格库定义稳定产物合同，游戏代码是具体消费方。
- 当前规格与游戏同仓，方便原型验证；未来接入外部生产平台时，应通过工作单、产物包和检查命令交接，而不是让平台理解并直接重写任意游戏文件。
- 游戏侧必须提供现有阶段键、资源路径、输入约束和项目版本；生产侧必须返回输出、依赖、版本和证据。
- 任何 Agent 都不得引入服务端或运行时 AI 调用来绕开静态运行边界。

## 4. 标准阶段

| 阶段 | 主责 Agent | 必需输入 | 标准输出 | 退出条件 |
| --- | --- | --- | --- | --- |
| 1. 需求受理 | `production_coordinator` | 目标、平台、时长、禁区、当前版本 | 工作单、范围、非目标、风险 | 决策无歧义或形成显式阻塞 |
| 2. 规格选型 | `specification_agent` | 工作单、规格目录、项目现状 | 基础规格、具体规格、依赖图 | 每项有 ID、路径、消费方和门禁 |
| 3. 具体化 | 对应域 Agent | 已选基础规格、创意或技术输入 | `approved` 具体规格 | 无含糊字段或未登记待决策 |
| 4. 并行生产 | 内容/工程/视觉 Agent | 已批准规格、冻结接口 | 目标文件、资源、生成记录 | 自检通过且未越界修改 |
| 5. 确定性集成 | `implementation_agent` | 各域输出、脚本顺序、运行时合同 | 可由 `index.html` 消费的项目 | 引用、加载顺序和状态闭合 |
| 6. 自动质量门 | `qa_agent` | 可运行项目、验收矩阵 | L0-L2 结果、缺陷 | 必需检查全绿 |
| 7. 体验验收 | `browser_qa_agent` | 真实浏览器、视口、流程矩阵 | 截图、状态、控制台记录 | 关键路径和失败恢复通过 |
| 8. 发布归档 | `production_coordinator` | 产物、证据、偏差、提交 | 验收报告、版本与 Pages | 可从规格追溯到线上版本 |

生产 Agent 与最终验收 Agent 必须使用不同上下文重新检查。实现者的口头结论不是验收证据。

## 5. 玩法与工程改动工作流

适用：任务阶段、移动、轻功、碰撞、队友 AI、首领、输入、HUD 或模块边界变更。

```text
冻结受影响 DSN / ENG 具体规格
  → 标出共享接口所有者
  → 修改最小模块
  → node --check + 项目契约检查
  → 逻辑与失败恢复回归
  → 桌面真实输入
  → 手机横/竖屏
  → 完整任务与发布回归
```

最少重验：

- 任务阶段和目标文案一致。
- `render_game_to_text` 暴露的新旧字段向后兼容。
- `advanceTime` 不与常规 RAF 重复推进。
- `file://`、HTTP 和 Pages 至少各检查一次相关启动边界。
- 输入变更同时检查键盘、鼠标和触控消费方。
- 状态机、碰撞或战斗改动必须覆盖失败、复活或重置。

## 6. 内容与数值批次工作流

适用：一条任务、一个遭遇、一组角色、一批 UI 文案或一轮平衡调整。

1. 冻结角色、阶段、敌人和技能 ID。
2. 在 `DSN.*` 具体规格中写出触发、推进、完成、失败和重复交互。
3. 明确配置值的唯一所有者；当前战斗常量分别位于 `src/config.js` 与 `src/combat.js`，变更前必须核对消费位置。
4. 内容 Agent 只提交结构化参数和文案；新增系统能力必须退回规格阶段。
5. QA 对正向、失败、重试、队令、治疗和首领破招分别取证。
6. 数值通过不等于节奏通过；目标 10–15 分钟仍需人工或真实玩家计时证据。

## 7. 视觉批次工作流

适用：图像生成、纹理、程序化模型、材质、天气、VFX 或 UI 构图。

```text
批准风格与消费尺寸
  → 生成清单和禁止项
  → 单资源生成 / 建模
  → 格式、尺寸、magic bytes、来源检查
  → 资源路径与材质接入
  → file:// 安全路径与 HTTP 原图路径
  → 桌面、手机最终缩放截图
  → 视觉偏差与性能结论
```

规则：

- 概念参考只提供设计语言，不是逐像素编辑目标。
- 每张图像保存完整提示词、源尺寸、最终尺寸与约束。
- 图像文件生成成功只算 L0；必须在游戏相机、雾、光照和 HUD 下验收。
- 纹理变更必须检查 UV、重复倍率、色彩空间和移动端显存。
- `file://` 不能安全上传本地位图时，必须使用已批准的同色系内存纹理，不得保留控制台错误。

## 8. 发布工作流

```text
工作区与变更范围检查
  → 静态语法和项目本地契约
  → file:// 冒烟
  → 完整任务 / 自然首领 / 防守 / 碰撞
  → 桌面鼠标 / 手机横屏 / 手机竖屏
  → 明确提交并推送功能分支
  → fast-forward main
  → 等待 GitHub Pages built
  → 检查线上资源与真实浏览器状态
  → 填写验收报告
```

发布条件：

- `main` 与目标提交一致，工作区无未提交产品文件。
- Pages 构建状态为 `built` 且提交 SHA 匹配。
- 在线 `index.html` 和新增静态资源返回成功状态。
- 在线浏览器的 `visualAssets`、任务状态和控制台满足相关规格。
- 任何测试环境自身的网络或字体问题必须与页面错误分开记录，不得伪装成产品通过或失败。

## 9. 并行边界

可以并行：

- 阶段键和角色 ID 冻结后，任务文案、视觉资源和测试矩阵分域生产。
- 材质 API 冻结后，纹理生成与角色/世界接入方案并行。
- 世界查询 API 冻结后，战斗 AI、UI 快照和浏览器脚本并行。
- 具体规格批准后，不同文档或完全不重叠的文件由不同 Agent 编写。

必须串行：

- 具体规格批准后才能修改产品代码。
- `index.html` 脚本顺序、`src/config.js`、公共状态字段和资源目录由单一所有者修改。
- L0/L1 失败时不能开始正式 L3 截图。
- 发布提交完成后才能把线上截图登记为该版本证据。

## 10. 变更控制

每个跨产物变更至少登记：

| 字段 | 内容 |
| --- | --- |
| 变更 ID | `CHG-YYYYMMDD-NNN` |
| 触发原因 | 缺陷、规格澄清、体验改进或依赖变化 |
| 影响规格 | 基础与具体规格 ID |
| 影响产物 | 文件、资源、状态、输入和证据 |
| 兼容策略 | 保持接口、迁移或明确破坏性变化 |
| 回滚点 | 提交或可恢复文件 |
| 重验范围 | 所需 L0-L3 和消费方 |

阶段键、资源路径、脚本顺序、状态字段、Three.js 版本、存档或输入合同默认属于发布级变化。

## 11. 失败处理

- 生成失败：保留已验证资源和注册路径，不提交半批结果。
- 静态检查失败：退回生产 Agent，禁止进入正式体验验收。
- 浏览器失败：登记复现步骤、预期、实际、视口、状态和截图。
- 规格不可实现：退回规格 Agent，不能由实现 Agent 降低目标。
- `file://` 与 HTTP 行为不同：两条路径分别保留证据，不能只测其中一条。
- 外部发布或网络不稳定：用仓库提交、Pages API、静态资源 HTTP 和持久浏览器交叉验证。

## 12. 最小命令集

项目不依赖 npm 构建。工程和规格批次至少运行：

```bash
node scripts/validate-project.mjs
node --check src/config.js
node --check src/materials.js
node --check src/entities.js
node --check src/audio.js
node --check src/world.js
node --check src/ui.js
node --check src/combat.js
node --check src/core.js
git diff --check
```

浏览器类批次还必须依据 `05-quality-products.md` 运行真实 `file://`、HTTP、目标移动视口和完整任务检查。`window.advanceTime` 用于确定性验证，但至少保留一组真实键盘、鼠标或触控输入证据。

## 13. 归档结构

```text
project/
├─ product-specs/             # 规格、Agent、工作流、模板与基线报告
├─ assets/                    # 运行时图像与来源说明
├─ src/                       # 运行时模块
├─ scripts/                   # 项目本地静态契约检查
├─ index.html                 # 静态入口与脚本顺序
├─ notes.md                   # 迭代与问题记录
└─ README.md                  # 玩家与开发入口
```

规格升级时提升版本并记录影响；不得用一个临时偏差覆盖后续所有批次。

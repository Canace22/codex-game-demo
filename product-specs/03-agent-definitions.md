# Agent 定义

## 1. 通用输入与交付

所有 Agent 开始前必须读取：项目画像、工作单、相关具体规格、直接依赖、当前提交和允许修改路径。

统一交付内容：

```text
产出：规格 ID、文件或资源路径
验收：执行命令、实际结果、证据路径
偏差：ID、影响、状态、责任人
风险：未覆盖场景和建议下一批
```

任何必需条件未满足时，不得标记 `verified`。

## 2. production_coordinator

使命：把需求拆成可独立验收的批次，维护范围、依赖、唯一写入者、回滚点和发布节奏。

可以决定：批次边界、顺序、文件所有者、最低门禁。

必须升级：产品形态变化、新平台、破坏性合同、外部发布或删除权限。

输出：项目画像、工作单、依赖图、发布和归档结论。

完成条件：每项产物都能从需求追溯到输出和证据。

## 3. specification_agent

使命：选择基础规格，把自然语言需求实例化为精确合同。

可以决定：规格拆分、ID、依赖、字段结构和可测完成条件。

必须升级：目标互相冲突、成功不可测、缺少关键产品决策。

输出：具体规格、验收矩阵、非目标和差异项。

完成条件：生产 Agent 无需猜测参数、路径、消费方或失败行为。

## 4. design_content_agent

使命：定义黄金路径、状态、角色/对象、玩法规则、数值和玩家反馈。

可以决定：批准范围内的文案细化与数值建议。

必须升级：新增系统能力、新公共状态、范围或平台扩张。

输出：流程表、内容表、规则、数值、UI 文案和逻辑测试案例。

完成条件：正向、失败、恢复和重复交互都可由结构化状态验收。

## 5. implementation_agent

使命：在项目现有架构内实现批准规格，保持模块边界和可测试性。

可以决定：内部算法、小函数拆分、兼容策略和低风险性能实现。

必须升级：公共 ID/字段/入口破坏、依赖升级、服务端或安全边界变化。

输出：代码、配置、资源注册、项目本地检查和调试接口。

完成条件：真实消费方可运行，L0–L2 通过，受影响输入和恢复路径可观察。

## 6. visual_agent

使命：生产并接入符合主题、可读、原创且性能受控的视觉媒体产物。

可以决定：批准范围内的构图、细节、压缩、材质和特效参数。

必须升级：新风格方向、身份重设、资源键变化、版权或性能预算冲突。

输出：图像、模型、纹理、材质、VFX、UI 样式、来源记录和消费截图。

完成条件：格式和来源通过 L0，实际接入通过 L2，目标镜头与视口通过 L3。

## 7. qa_release_agent

使命：用独立上下文验证结构、逻辑、集成、体验和发布，不接受生产者口头结论。

可以决定：缺陷严重度、复现步骤、回归范围和验收结论。

必须升级：规格冲突、环境不可复现、需要降低门禁、缺发布授权。

输出：测试结果、状态、截图、错误与网络摘要、偏差和验收报告。

完成条件：按风险完成 L0–L3；发布时提交、构建、线上消费方和回滚点一致。

## 8. 标准 Agent 提示骨架

```text
你是 <agent_id>。
只执行工作单 <work_order_id> 的单一目标。
先读取项目画像、具体规格、直接依赖和当前实现。
只能修改 allowed_paths，保留 frozen_contracts。
完成 outputs，并执行 required_gates。
返回产出、验收、证据、偏差、风险；失败时给出最短复现和阻塞责任方。
不得引入非目标能力，不得把存在的实现直接标记 verified。
```

## 9. 交接顺序

```text
production_coordinator
  → specification_agent
    → design_content_agent / visual_agent
      → implementation_agent
        → qa_release_agent
          → production_coordinator 归档
```

当项目已经有明确规格时，可以跳过内容生产，但不能跳过项目画像、消费合同和独立 QA。
